# Домашнее задание

## Что надо было сделать

Возьмите проект, над которым вы работаете или хотели бы работать, — сайт, бот, мобильное приложение — и составьте для него модель доступа в файле access-model.md.

- Четыре роли, для каждой — учётная запись, группы, каталоги, что роль может и чего не может.

- Каталоги проекта в /srv с группой и правами числом и буквами.

- Скрипт setup-team.sh, который создаёт группы, пользователей и каталоги. Запустите его в учебной виртуальной машине и приложите вывод id для каждого пользователя и ls -l каталогов.

- Пять строк таблицы тестов доступа с ожидаемым и фактическим результатом.

## Решение

Проект: Telegram-бот получает фото конспекта, ИИ переводит его в Markdown, затем бот создаёт Pull Request в репозиторий.

### Роли

| Роль | Учётная запись | Группы | Каталоги | Может | Не может |
|---|---|---|---|---|---|
| Руководитель | team-lead | notes-code, notes-data, notes-git, sudo | Все | Управлять сервером через sudo; проверять и сливать PR | Менять защищённые системные файлы без sudo |
| Разработчик | dev | notes-code | src | Читать и менять код бота | Открывать фото, конспекты и repo; использовать sudo |
| Тестировщик | qa | notes-data | photos, notes | Сравнивать конспекты с фото, создавать тестовые материалы | Открывать src и repo; использовать sudo |
| Бот | bot | notes-code, notes-data, notes-git | src (чтение), photos, notes, repo | Обрабатывать фото, сохранять конспекты, создавать PR | Создавать файлы в src; сливать PR; использовать sudo |

`bot` — Linux-аккаунт бота. Пользователи Telegram не получают доступ к серверу. Права на создание и слияние PR задаются отдельно в GitHub.

### Каталоги

| Каталог | Владелец:группа | Права числом | Права буквами |
|---|---|---|---|
| /srv/notes-bot | root:root | 0755 | drwxr-xr-x |
| /srv/notes-bot/src | dev:notes-code | 2750 | drwxr-s--- |
| /srv/notes-bot/photos | root:notes-data | 2770 | drwxrws--- |
| /srv/notes-bot/notes | root:notes-data | 2770 | drwxrws--- |
| /srv/notes-bot/repo | root:notes-git | 2770 | drwxrws--- |

`2` включает setgid: новые файлы наследуют группу каталога. В `src` группа может только читать список файлов и входить в каталог; в остальных рабочих каталогах — также создавать и удалять файлы.

### Скрипт

```bash
sudo bash setup-team.sh
id team-lead dev qa bot
ls -l /srv/notes-bot
```

### Таблица тестов доступа

Фактические результаты заполняются после выполнения команд в учебной ВМ.

| № | Пользователь | Команда | Ожидается | Получено |
|---|---|---|---|---|
| 1 | team-lead | `sudo -u team-lead ls /srv/notes-bot/repo` | разрешено | не запускалось |
| 2 | dev | `sudo -u dev touch /srv/notes-bot/src/test.txt` | разрешено | не запускалось |
| 3 | qa | `sudo -u qa touch /srv/notes-bot/notes/check.md` | разрешено | не запускалось |
| 4 | bot | `sudo -u bot touch /srv/notes-bot/repo/summary.md` | разрешено | не запускалось |
| 5 | bot | `sudo -u bot touch /srv/notes-bot/src/blocked.txt` | отказ в доступе | не запускалось |
