# Таблица тестов доступа · команда mobile-app

| №   | Пользователь | Команда                                          | Ожидается       | Получено           |
| --- | ------------ | ------------------------------------------------ | --------------- | ------------------ |
| 1   | lead         | `sudo -u lead touch /srv/mobile/src/lead.txt`    | разрешено       | разрешено          |
| 2   | lead         | `sudo -u lead ls /srv/mobile/reports`            | разрешено       | разрешено          |
| 3   | dev          | `sudo -u dev touch /srv/mobile/src/main.kt`      | разрешено       | разрешено          |
| 4   | dev          | `sudo -u dev ls /srv/mobile/reports`             | отказ в доступе | Отказано в доступе |
| 5   | qa           | `sudo -u qa touch /srv/mobile/reports/test-1.md` | разрешено       | разрешено          |
| 6   | qa           | `sudo -u qa ls /srv/mobile/src`                  | отказ в доступе | Отказано в доступе |
| 7   | guest        | `sudo -u guest ls /srv/mobile/src`               | отказ в доступе | Отказано в доступе |
| 8   | guest        | `sudo -u guest ls /srv/mobile/reports`           | отказ в доступе | Отказано в доступе |

## Схема ролей

| Роль              | Учётная запись | Группы                      | Каталоги     | Может                                                    | Не может                                             |
| ----------------- | -------------- | --------------------------- | ------------ | -------------------------------------------------------- | ---------------------------------------------------- |
| руководитель      | lead           | mobile-dev, mobile-qa, sudo | src, reports | Работать с кодом и отчётами; администрировать через sudo | Без повышения прав менять защищённые системные файлы |
| разработчик       | dev            | mobile-dev                  | src          | Читать и создавать файлы в src                           | Открывать reports; использовать sudo                 |
| тестировщик       | qa             | mobile-qa                   | reports      | Читать и создавать отчёты в reports                      | Открывать src; использовать sudo                     |
| внешний сотрудник | guest          | только личная группа        | —            | Работать в домашнем каталоге                             | Открывать src и reports; использовать sudo           |

## Почему постоянная работа под root опасна

1. Опечатка в пути может удалить системные файлы: `/etc/app` вместо `./etc/app`.
2. Вредный скрипт или программа с ошибкой получает возможность менять любые файлы системы.
3. Созданные root файлы проекта могут быть недоступны для изменения другим участникам.
